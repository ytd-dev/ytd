# YMD — загрузчик треков из Яндекс Музыки

**Версия 0.0.2.** Модульный консольный загрузчик: скачивает **треки, альбомы, дискографии артистов и плейлисты** с `music.yandex.ru` через [неофициальный API](https://github.com/MarshalX/yandex-music-api) (никакого парсинга HTML и «серых» эндпоинтов), для `-q 192/256/320` всегда отдаёт **строго MP3** (при наличии FLAC перекодирует lossless в MP3 запрошенного битрейта, lossy-источник не апскейлится выше API), `-q 2` сохраняет FLAC или обязательный MP3 (никакого сырого `.m4a`), конвертирует при необходимости (FFmpeg), пишет теги (ID3v2.4 / v2.3, MP4-атомы, Vorbis), встраивает обложку и тексты песен, сохраняет списки и отчёты.

> **Раскладка каталога корректная:** в корне лежат `pyproject.toml`, `README.md` и пакет `ymd/` (модули `api/`, `cli/`, `core/`, `filesystem/`, `metadata/`, `config.py` — внутри `ymd/`). Каталог устанавливается «как есть»: `pip install .` / `pipx install .` из этого каталога.

```bash
ymd --url https://music.yandex.ru/album/34454581/track/134036245 --quality 2
```

Ключевые свойства:

* **Честное расширение файла** определяет то, что реально вернул API (контейнер/кодек), а не ожидания пользователя. Нет AAC-потока (типично для подкастов и аудиокниг) — будет `.mp3`, и в логе прямо написано почему.
* **Битрейт никогда не выше источника**: `-q 320` для трека с источником 256 кбит/с даст 256 (в логе: `API вернул: … заявленный битрейт=256`).
* **Ошибки одного трека не роняют прогон**: недоступный или сбойный трек помечается, остальные скачиваются; итоговая статистика точна.
* **Ссылка на трек** всегда попадает в теги (`WOAF` в MP3, `©cmt` в M4A, `comment` во FLAC).
* **Безопасная запись в файловую систему**: чужие файлы не затираются, недокачанный файл не выдаётся за готовый (см. раздел 8).

## 1. Быстрый старт

Четыре способа на выбор: **установка из GitHub** (публичный репозиторий `ytd-dev/ytd`, подробности в разделе 2.6), **pipx из этого каталога** (рекомендуется для локальной копии — отдельное окружение, команда `ymd` глобально), **pip + venv** (классика для рабочего проекта) и **запуск из исходников без установки**.

```bash
# 1) из GitHub — нужен git в PATH (подробно: раздел 2.6)
pipx install "git+https://github.com/ytd-dev/ytd.git"

# 2) pipx из этого каталога — один раз установили, команда ymd доступна из любой папки
pipx install .

# 3) pip в виртуальном окружении
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install .

# 4) без установки — из этого каталога (здесь лежит каталог ymd/)
python -m ymd --url https://music.yandex.ru/album/34454581/track/134036245 -q 2
```

Дальше — токен (раздел 3): проще всего один раз пройти интерактивный вход, токен сам сохранится в `~/.ymd/.env`.

## 2. Установка

### 2.1. Требования

| Компонент | Нужно | Примечание |
|---|---|---|
| Python | **3.10+** | проверялось на 3.12; кросс-платформенная приёмка пройдена в Windows и Ubuntu |
| FFmpeg | в `PATH` (`ffmpeg`) | нужен, когда вызывается конвертация/ремукс: `--force-mp3`, фоллбэк AAC→MP3 и ремукс FLAC-потока в `.flac` при `-q 2`, транскодирование FLAC→MP3 и любого lossy-потока не в свой битрейт при `-q 192/256/320`. Без FFmpeg режимы `-q 0/1` работают как обычно, а в режимах, где нужна конвертация, скрипт предупреждает и оставляет файл в нативном формате/расширении. Режим `--recheck` работает через `mutagen`, FFmpeg для него не нужен (в справке `--help` упомянут `ffprobe` — фактически он не вызывается) |
| Зависимости Python | `yandex-music`, `mutagen`, `requests` | ставятся автоматически; сторонних библиотек (в т.ч. для `.env`) не используется |
| git | только для установки из GitHub (раздел 2.6) | `pip`/`pipx` сами клонируют репозиторий через `git`; проверьте `git --version` |
| Опционально | `pysocks` | только для прокси `socks5://…` |

Локальные способы установки (разделы 2.3–2.5) ставятся **из корневого каталога проекта** — того, где лежат `pyproject.toml`, `README.md` и каталог `ymd/` (установка из GitHub, раздел 2.6, ставится напрямую из репозитория):

```
ytd/
├── pyproject.toml     метаданные пакета: имя ymd, версия, зависимости, команда ymd
├── README.md
└── ymd/               сам код (см. раздел 4)
    ├── api/  cli/  core/  filesystem/  metadata/
    └── config.py  exceptions.py  __init__.py  __main__.py
```

Поэтому `pip install .` / `pipx install .` из корневого каталога работают без каких-либо подготовительных действий, и все команды установки ниже (`pipx install .`, `pip install .`, `python -m ymd`) выполняются из этого каталога как есть.

### 2.2. Установка FFmpeg (Windows, Linux, macOS)

FFmpeg нужен только когда задействуется конвертация или перепаковка потоков: флаг `--force-mp3` (AAC → MP3 64/192), фоллбэк AAC → MP3 и ремукс lossless FLAC-потока из контейнера MP4 в `.flac` при `-q 2`, а при `-q 192/256/320` — любое транскодирование в MP3 (FLAC → MP3 запрошенного битрейта, AAC → MP3, MP3 с другим битрейтом). FFmpeg **не обязателен** для обычного скачивания AAC (`-q 0/1`), сохранения нативного MP3 с битрейтом источника (когда он и так равен запрошенному или это фоллбэк `-q 2`) и режима проверки битрейтов `--recheck` (он работает через `mutagen`).

**Windows.** Проверить наличие: `where ffmpeg`. Если не найден — один из способов:

```powershell
winget install Gyan.FFmpeg     # самый быстрый (перезапустить терминал после установки)
scoop install ffmpeg           # альтернатива, если уже пользуетесь Scoop
```

Вручную: скачайте архив `ffmpeg-release-essentials.zip` с [gyan.dev/ffmpeg/builds](https://www.gyan.dev/ffmpeg/builds/) (или сборки [BtbN](https://github.com/BtbN/FFmpeg-Builds/releases)), распакуйте, например, в `C:\ffmpeg` (чтобы получилось `C:\ffmpeg\bin\ffmpeg.exe`) и добавьте папку `bin` в `PATH` (`Win+R` → `sysdm.cpl` → «Дополнительно» → «Переменные среды…» → `Path` → «Создать» → `C:\ffmpeg\bin`). Перезапустите терминал и проверьте: `ffmpeg -version`.

**Linux (Ubuntu/Debian):**

```bash
sudo apt update && sudo apt install -y ffmpeg
```

**macOS:**

```bash
brew install ffmpeg
```

Проверка для всех систем: `ffmpeg -version`, а доступность в `PATH` — `where ffmpeg` (Windows) или `which ffmpeg` (Linux/macOS).

### 2.3. pipx (рекомендуемый способ)

`pipx` держит каждый CLI-пакет в собственном виртуальном окружении и добавляет команду `ymd` в `PATH`, не трогая системный Python.

```bash
# ставим pipx один раз
python -m pip install --user pipx
python -m pipx ensurepath        # добавить PATH; после этого открыть терминал заново

# установка из этого каталога (в нём лежит пакет ymd/)
pipx install .
# или из любого места, указав путь до каталога пакета (там, где лежит ymd/)
pipx install C:\path\to\ytd
# с поддержкой socks5-прокси (extra "proxy")
pipx install '.[proxy]'

# проверка и дальнейшая жизнь
pipx list
pipx runpip ymd show ymd         # сведения об установленном пакете
pipx upgrade ymd                 # обновить после выхода новой версии
pipx inject ymd pysocks          # добавить зависимость поверх установленной копии
pipx uninstall ymd               # удалить
```

После установки команда называется **`ymd`**, а не `python -m ymd`:

```bash
ymd --url https://music.yandex.ru/artist/23762456 --list-only
```

> **Важно про раскладку каталогов.** Пакет должен называться `ymd`: в корне проекта (рядом с `pyproject.toml`) лежит каталог `ymd/` с `__init__.py`. В репозитории раскладка именно такая, поэтому `pip`/`pipx` собирают полный пакет. Если же вы распаковали архив, где код лежит в папке с другим именем (например плоским списком модулей без `ymd/`), `pip`/`pipx` соберут **пустой** пакет: установка «пройдёт успешно», но команды `ymd` не появится. Исправление — создать подкаталог `ymd/` и перенести в него модули (`New-Item -ItemType Directory ymd`, затем `Move-Item api, cli, core, filesystem, metadata, config.py, exceptions.py, __init__.py, __main__.py ymd\`); если код лежит в папке с другим именем, можно переименовать её в `ymd`.
>
> **Проверка после установки:** `pip show -f ymd` — в списке файлов должны быть `ymd/__init__.py`, `ymd/cli/main.py` и т.д.; `ymd --version` должен напечатать `ymd 0.0.2`, а `ymd --help` — справку (Windows: `where ymd`, Linux/macOS: `which ymd`).

### 2.6. Установка из GitHub

Публичный репозиторий проекта — **[github.com/ytd-dev/ytd](https://github.com/ytd-dev/ytd)**, ветка по умолчанию — `main`. Раскладка репозитория: в корне лежат `pyproject.toml`, `README.md` и пакет `ymd/`, поэтому указывать `#subdirectory=` не нужно — `pip` и `pipx` сами вызовут `git`, соберут пакет из корня и поставят зависимости. Из дополнительного требуется только `git` в `PATH` (проверка: `git --version`).

```bash
# pipx — пакет в отдельном виртуальном окружении, команда ymd в PATH
pipx install "git+https://github.com/ytd-dev/ytd.git"

# pip — в текущее (в идеале виртуальное) окружение
python -m pip install "git+https://github.com/ytd-dev/ytd.git"

# с опциональным модулем socks5-прокси (extra "proxy")
python -m pip install "ymd[proxy] @ git+https://github.com/ytd-dev/ytd.git"
```

Варианты источника (синтаксис `git+…`, `@<тег>` и `@<ветка>` проверены на этом репозитории):

| Что ставим | Команда |
|---|---|
| актуальный `main` | `python -m pip install "git+https://github.com/ytd-dev/ytd.git"` |
| тег выпуска | `python -m pip install "git+https://github.com/ytd-dev/ytd.git@v0.0.2"` |
| ветка | `python -m pip install "git+https://github.com/ytd-dev/ytd.git@main"` |
| конкретный коммит | `python -m pip install "git+https://github.com/ytd-dev/ytd.git@<sha>"` |

> **Про версию.** После любой установки проверяем её командой `ymd --version` — должно быть `ymd 0.0.2`. Если напечаталась более старая версия, значит в `main` (или под этим тегом) на GitHub ещё лежит прошлый выпуск: теги репозитория — `git ls-remote --tags https://github.com/ytd-dev/ytd`, указатель ветки — `git ls-remote https://github.com/ytd-dev/ytd main`. Форма `…@v0.0.2` работает с того момента, как тег `v0.0.2` опубликован.

Обновление установки из git:

```bash
python -m pip install --upgrade "git+https://github.com/ytd-dev/ytd.git"   # pip заново клонирует ветку и переустанавливает пакет
pipx upgrade ymd                                                          # pipx помнит, откуда был установлен пакет
pipx install --force "git+https://github.com/ytd-dev/ytd.git@v0.0.2"       # если нужно перейти на другой тег/ветку
```

Удаление — обычная команда для способа установки: `python -m pip uninstall ymd` или `pipx uninstall ymd`.

### 2.7. Запуск без установки

Скачанный проект никуда ставить не обязательно — запускайте модуль из его корневого каталога:

```bash
python -m ymd --album-id 36526 -q 2
```

Модуль ищется в текущем каталоге, поэтому запускать нужно из папки, где лежит каталог `ymd/`: просто выполняйте команду из корня репозитория. Имя каталога с кодом при этом должно называться именно `ymd`: если код лежит в папке с другим именем (например `ymd-source/`), переименуйте её в `ymd`, а затем добавьте в `PYTHONPATH` каталог, **содержащий** папку `ymd/`:

```bash
# Windows cmd
set PYTHONPATH=C:\path\to\parent && python -m ymd --album-id 36526 -q 2
```
```bash
# Linux / macOS
PYTHONPATH=/path/to/parent python3 -m ymd --album-id 36526 -q 2
```

Зависимости Python (`yandex-music`, `mutagen`, `requests`) при запуске без установки должны быть доступны в том интерпретаторе, которым вы запускаете: поставьте их вручную — `python -m pip install yandex-music mutagen requests`.

## 3. Токен и `.env`

Для доступа к API нужен OAuth-токен Яндекс ID (для `-q 2` и FLAC — аккаунт **с действующей подпиской**).

### 3.1. Порядок поиска токена

1. флаг **`--token` / `-t`**;
2. переменная окружения **`YANDEX_MUSIC_TOKEN`**;
3. **`YANDEX_MUSIC_TOKEN` из файла `.env`**: сначала `./.env` в текущем каталоге, затем **`~/.ymd/.env`**;
4. если ничего не найдено — интерактивный **device flow**: скрипт покажет ссылку для подтверждения и код; в подсказке печатаются оба адреса — `https://ya.ru/device` и `https://oauth.yandex.ru/device`. Вы подтверждаете вход в браузере.

**Полученный в device flow токен автоматически сохраняется в `~/.ymd/.env`** — повторные запуски авторизации не требуют. На POSIX-системах файлу ставятся права `0600`. На Windows `chmod` работает ограниченно (только флаг «только чтение»), поэтому файл наследует права своего каталога — обычно это профиль пользователя: полный доступ у владельца и администраторов. Если компьютер общий, доступ можно ограничить вручную, например: `icacls "%USERPROFILE%\.ymd\.env" /inheritance:r /grant:r "%USERNAME%:F"`.

### 3.2. Файл `.env`

Формат — обычные строки `KEY=value`; значения можно брать в кавычки, пустые строки и строки с `#` игнорируются. Никаких сторонних библиотек (`python-dotenv` и т.п.) не нужно.

```ini
# ~/.ymd/.env  (или ./.env в текущем каталоге)
YANDEX_MUSIC_TOKEN=0.yyy.xxxxx_xxxxxxxxxxxxxxxxxxxxxxxxxx
```

Нюансы:

* `.env` можно сохранять в UTF-8 **с BOM** (так его пишут Блокнот и PowerShell 5.1) — BOM игнорируется, строка токена распознаётся нормально. Сама программа всегда пишет файл без BOM.
* `.env` читается **из текущего рабочего каталога**, поэтому при установке через `pipx` (запуск из любой папки) удобнее держать токен в глобальном `~/.ymd/.env`.
* Локальный `./.env` важнее глобального `~/.ymd/.env`, а переменная окружения важнее обоих файлов — удобно, чтобы временно запускаться под другим аккаунтом.
* `.gitignore` проекта содержит маски `.env` и `*.env` — токен не попадёт в репозиторий.
* `~/.ymd/` — ещё и кэш обложек (`~/.ymd/covers`); удаление этой папки безопасно сбрасывает кэш.
* Токен со временем истекает: при ошибке авторизации просто обновите строку в `~/.ymd/.env` или удалите её — при следующем запуске начнётся device flow.

### 3.3. Токен в переменных окружения

```bat
:: Windows cmd
set YANDEX_MUSIC_TOKEN=<ВАШ_ТОКЕН>
```
```powershell
# Windows PowerShell
$env:YANDEX_MUSIC_TOKEN = "<ВАШ_ТОКЕН>"
```
```bash
# Linux / macOS
export YANDEX_MUSIC_TOKEN=<ВАШ_ТОКЕН>
```

## 4. Структура проекта

```
ymd/
├── __main__.py          точка входа (python -m ymd)
├── config.py            AppConfig (все настройки), константы, плейсхолдеры путей

│   ├── client.py        создание клиента, ретраи, прокси, device flow, сохранение токена в ~/.ymd/.env

├── cli/
│   ├── parser.py        парсер аргументов (все ключи — здесь) + чтение токена из .env
│   └── main.py          оркестратор: разбор → клиент → источник → скачивание → отчёты
├── core/
│   ├── quality.py       матрица --quality: параметры запроса, выбор потока и план сохранения
│   ├── formats.py       контейнер/кодек API → расширение, план ремукса
│   ├── downloader.py    скачивание в .part, нумерация, коллизии имён, отчёты, статистика
│   └── converter.py     ffmpeg: конвертация в MP3, ремукс в FLAC (-y/-n)
├── metadata/
│   ├── tags.py          теги: ID3v2.4/v2.3 (MP3), MP4-атомы (M4A), Vorbis+Picture (FLAC)
│   ├── covers.py        обложки: размеры, запасные размеры, кэш ~/.ymd/covers, определение MIME
│   └── lyrics.py        тексты песен (TEXT / LRC)
└── filesystem/
    ├── naming.py        --path-pattern, плейсхолдеры, санитайзер имён
    └── paths.py         безопасная запись, уникальное имя «файл (1).mp3», temp-файлы
```

## 5. Источник: что качаем

Источник задаётся **только** взаимоисключающими флагами (позиционных аргументов нет):

| Ключ | Значение |
|---|---|
| `--url URL` | любая ссылка `music.yandex.ru` |
| `--track-id ID` | ID трека (число) |
| `--album-id ID` | ID альбома (число) |
| `--artist-id ID` | ID артиста — вся дискография |
| `--playlist-id ID` | `владелец/номер`, UUID, `lk.<uuid>` или `likes` («Мне нравится» текущего аккаунта) |

Поддерживаемые формы ссылок:

```
https://music.yandex.ru/album/34454581                      альбом
https://music.yandex.ru/album/34454581/track/134036245      трек внутри альбома
https://music.yandex.ru/track/134036245                     трек
https://music.yandex.ru/artist/23762456                     артист (дискография)
https://music.yandex.ru/artist/23762456/tracks              треки артиста
https://music.yandex.ru/artist/23762456/podcasts            подкасты артиста
https://music.yandex.ru/playlists/<uuid>                    плейлист по UUID (любой публичный)
https://music.yandex.ru/playlists/lk.<uuid>                 «Мне нравится» — любой открытый аккаунт
https://music.yandex.ru/playlists/ar.<uuid>                 автоплейлист артиста
https://music.yandex.ru/users/<login>/playlists/<kind>      старый формат (число: 0/1/2/3/1000+)
https://music.yandex.ru/users/<login>/playlists/likes       «Мне нравится»: только свой аккаунт
```

Пояснения:

* **Старый числовой формат работает** и для своих, и для чужих плейлистов, включая `…/playlists/3` = «Мне нравится» чужого пользователя (браузер такие ссылки переписывает на новые, а API-маршрут жив). Состав треков совпадает с новым форматом (`lk.<uuid>` / `<uuid>`), вплоть до порядка.
* **`lk.<uuid>`** всегда берётся по своему UUID (`GET /playlist/<uuid>`): чужой `lk.…` отдаёт чужие лайки, приватный — понятную ошибку.
* **Keyword `likes`** работает только для своего логина; для чужого — явная ошибка с подсказкой взять постоянный адрес `lk.<uuid>` (или старый адрес `…/playlists/3`). Подмены своими лайками нет.
* У своего аккаунта `…/playlists/3` и keyword `likes` могут давать слегка разный состав — это расхождение на стороне Яндекса, оба маршрута корректны.
* `?utm_…` и прочие query-хвосты ссылок игнорируются. Мёртвая ссылка: `rc=1` с текстом вида `Плейлист не найден: …`.
* **Ссылку с `?utm_…` в cmd, PowerShell и bash берите в кавычки.** В cmd и bash символ `&` разделяет команды, поэтому команда вида
  `ymd --url https://music.yandex.ru/playlists/lk.<uuid>?utm_source=web&utm_medium=copy_link -q 320`
  распадается на две: `ymd` запускается **без `-q 320`** (то есть с качеством по умолчанию `-q 0` → AAC 64 → `.m4a`), а из хвоста `utm_medium=copy_link -q 320` оболочка ругается вида `"utm_medium" не является внутренней или внешней командой`. В PowerShell (5.1 и 7) неэкранированный `&` делает строку неразбираемой. Правильно — в кавычках:
  `ymd --url "https://music.yandex.ru/playlists/lk.<uuid>?utm_source=web&utm_medium=copy_link" -q 320`
  (или просто отрезать хвост после `?`). Проверить, что действительно дошло до программы, можно по строкам `Источник:` и `Качество:` в шапке запуска (раздел 6).
* **`…/artist/<id>/podcasts`**: отдельного маршрута `/artists/<id>/podcasts` у API нет (он отвечает `404 not-found`), поэтому подкасты собираются из релизов артиста (`GET /artists/<id>/direct-albums`) с `meta_type == 'podcast'`, с пагинацией.

## 6. Качество: `--quality` (`-q`)

| Значение | Что запрашивается | Что будет на диске |
|---|---|---|
| `0` (по умолчанию) | AAC 64 | `.m4a` без конвертации; у подкастов без AAC-потока — честный `.mp3`. FLAC не опрашивается |
| `1` | AAC 192 | `.m4a` (фактический VBR ниже заявленных 192 — это норма кодека, а не потеря качества). FLAC не опрашивается |
| `2` | максимум: сначала lossless | FLAC → `.flac` (ремукс из контейнера MP4); **если FLAC нет — обязательная конвертация в `.mp3`** с битрейтом источника (обычно 256), сырого `.m4a` не будет |
| `192` / `256` / `320` | MP3 указанного битрейта **и FLAC** (запрос `lossless`) | строго `.mp3`: есть FLAC → lossless скачивается и перекодируется в MP3 **запрошенного** битрейта (CBR через FFmpeg); lossy-источник → MP3 битрейта `min(запрошенный, источник)` (апскейла нет) |

* **Наличие FLAC проверяется в режимах `2`, `192`, `256`, `320`** — запрос `/get-file-info` идёт с `quality=lossless`. Если у трека есть lossless-поток, он и становится источником для MP3: `-q 320` для трека с FLAC даст ровно 320 kbps CBR, перекодированные из lossless.
* **Если источником уже является MP3 нужного битрейта, конвертация пропускается** — файл сохраняется напрямую, без вызова FFmpeg.
* `--force-mp3` — сконвертировать AAC в MP3 при `-q 0/1` (с FFmpeg: MP3 `64`/`192` kbps CBR соответственно; без FFmpeg — предупреждение, файл остаётся `.m4a`). Для `2/192/256/320` флаг **не нужен и не принимается** (код возврата 2) — эти режимы и так отдают `.mp3`/`.flac`.
* `--compatibility-level 1` — режим максимальной совместимости: **никогда не запрашивать FLAC — ни при `-q 2`, ни при `-q 192/256/320`** (FLAC → MP3 в этих режимах отключается, работает правило `min(запрошенный, источник)`) **и** писать MP3 в тегах **ID3v2.3** вместо v2.4 (лучше читается старыми плеерами и авто). По умолчанию `0`.
* Ошибка конвертации (в том числе отсутствующий FFmpeg) **не прерывает закачку** — файл сохраняется в исходном формате с предупреждением.
* **Шапка запуска печатает фактическое качество**, с которым программа будет работать:
  `Качество: -q 320 → MP3 320kbps CBR (FLAC проверяется; без FLAC — не выше источника)`.
  Строка зависит и от `--force-mp3`, и от `--compatibility-level 1`. Если в ней видно не то, что набрано в командной строке, флаг до программы не дошёл — чаще всего из-за `&` в ссылке без кавычек (см. раздел 5). Реализация: `core/quality.py` → `mode_description`; в режиме `--recheck` без источника строки нет (качество там не используется).
* Вывод по каждому треку информативен (реальные прогоны v0.0.2):

  ```
  Качество: -q 320 → MP3 320kbps CBR (FLAC проверяется; без FLAC — не выше источника)
  …
  [1/1] [FLAC] Загружается DEAD BLONDE - Бесприданница.mp3
    API вернул: lossless FLAC (источник)
    Будет сконвертирован: .mp3 (FLAC -> MP3 320kbps CBR)
  INFO: [FFmpeg] Транскодирование: FLAC -> MP3 320kbps CBR

  [1/1] [AAC 192kbps] Загружается Laid Back - So This Is X-mas.mp3
    API вернул: контейнер=MP4 кодек=AAC заявленный битрейт=192
    Будет сохранен с расширением: .mp3 (AAC -> MP3 192kbps)
  INFO: [FFmpeg] Транскодирование: AAC -> MP3 192kbps
  ```

  Первый трек — lossless есть, MP3 собран из FLAC ровно 320000 бит/с; второй — lossless нет, битрейт ограничен источником (192), апскейла нет.

## 7. Куда сохранять: `--dir`, `--path-pattern`

* `--dir PATH` — корень (по умолчанию текущий каталог).
* `--path-pattern PATTERN` — путь внутри `--dir`. **Если ключ не задан явно,
  шаблон выбирается автоматически по типу распознанного источника:**

| Источник | Тип | Шаблон по умолчанию |
|---|---|---|
| `/track/<id>`, `/album/<id>/track/<id>`, `--track-id` | одиночный трек | `{artists} - {title}` |
| `/album/<id>`, `--album-id` | альбом целиком | `{artists} - {album}/{track_number_padded} {artists} - {title}` |
| `/artist/<id>`, `--artist-id` | дискография артиста | `{artists}/{album}/{track_number_padded} {artists} - {title}` |
| `/artist/<id>/tracks` | все треки артиста | `{artists}/{artists} - {title}` |
| `/artist/<id>/podcasts` | подкасты артиста | `{artists}/{artists} - {title}` |
| `/playlists/ar.<uuid>` | автоплейлист треков артиста | `{artists}/{artists} - {title}` |
| `/playlists/<uuid>`, `--playlist-id <uuid>` | плейлист по UUID | `{playlist}/{artists} - {title}` |
| `/playlists/lk.<uuid>` | чужие «Мне нравится» по UUID | `{playlist}/{artists} - {title}` |
| `/users/<login>/playlists/<kind>` | плейлист старого формата | `{playlist}/{artists} - {title}` |
| `--playlist-id likes` | свои «Мне нравится» | `{playlist}/{artists} - {title}` |

  Выбор шаблона печатается в консоли (`Шаблон пути выбран по типу источника (плейлист): …`).
  Одиночный трек без `--path-pattern` сохраняется прямо в `--dir`, без промежуточных
  папок; плейлист — в папку с **оригинальным названием плейлиста** из Яндекс Музыки
  (`playlist.title`, при пустом имени — `Плейлист`).
  Если `--path-pattern` указан явно, он используется без изменений — контекст на него не влияет.

Плейсхолдеры:

| Плейсхолдер | Что подставляет |
|---|---|
| `{id}` | ID трека |
| `{title}` | название трека |
| `{artists}` / `{artist}` | все артисты / первый артист |
| `{album}` / `{album_artist}` | альбом / альбомный артист |
| `{playlist}` | название плейлиста-источника (для одиночных треков/альбомов — пусто) |
| `{track_number}`, `{track_number_padded}` | **сквозной** номер в релизе (01…32) — уникален, спасает многодисники |
| `{real_track_number}`, `{real_track_number_padded}` | номер из API внутри тома (в каждом томе с 1) |
| `{disc_number}` | номер тома/диска |
| `{year}` | год (цепочка: `album.year` → `album.release_date` → `track.pub_date`) |
| `{genre}`, `{duration}`, `{bitrate}` | жанр / длительность, с / битрейт |
| `{extension}`, `{extension_no_dot}` | `.m4a` / `m4a` |

Пустые значения плейсхолдеров вырезаются — путь просто становится короче
(поэтому `{playlist}` вне контекста плейлиста не создаёт пустую папку).

## 8. Как ведёт себя программа при записи файлов

* **По умолчанию чужие файлы не затираются.** Если в целевом каталоге уже есть файл с таким именем, новый трек получает `Название (1).m4a` + предупреждение `⚠️ Совпадение имён: …`. То же касается конвертации: FFmpeg вызывается с `-n` (запрет перезаписи), а при `--overwrite` — с `-y`.
* **`--skip-existing`** — пропускать треки, чьё имя (без расширения) уже есть **в целевом каталоге** этого трека: `⏭️ Пропущено (уже есть): N`. Проверка идёт только по файлам `.mp3/.m4a/.flac/.mp4` в той папке, куда пошёл бы файл, — а не по всему дереву `--dir`.
* **`--overwrite`** — разрешает перезапись существующего пути (и скачивание, и конвертацию).
* **Атомарность скачивания.** Данные пишутся во временный файл `имя.part`, и только после успешной загрузки переименовываются в готовый файл с реальным расширением. Поэтому оборванная загрузка не оставляет «готовый» файл и не будет воспринята как уже скачанная; `.part` удаляются при ошибке.
* **Конвертация не приписывает успех наугад:** успех засчитывается только если целевой файл реально создан или перезаписан в этом запуске (FFmpeg 9.x умеет возвращать код 0, ничего не записав). Исходник при неудаче сохраняется.
* **`--unsafe-path`** — отключить санитайзер имён (символы Windows/POSIX сохраняются как есть; небезопасно, ФС может отказать). Служебные `/` `\` из значений плейсхолдеров вырезаются всегда на уровне разбора пути.

## 9. Метаданные: обложка, тексты, теги

### Обложка

* Встраивается в теги **по умолчанию** (`--embed-cover` — явное включение).
* `--no-embed-cover` — не встраивать, а класть рядом `cover.jpg`.
* `--cover-resolution original|N` — превью Яндекса: квадрат `100/200/300/600/1000` или `original`; по умолчанию `600`. Недостающий размер (например 500) автоматически заменяется ближайшим доступным: **запрошенный → 1000 → 600 → 300 → 200 → 100**.
* Если **родной размер** конкретной обложки меньше запрошенного, CDN отдаёт картинку родного размера без апскейла (например 500×508 вместо 600×600). Это не потеря качества — это максимум источника.
* Тип картинки (JPEG/PNG) определяется по сигнатуре байтов, а не по имени URL, — в том числе при чтении из кэша.
* Кэш: in-memory (альбом) + диск `~/.ymd/covers`.

### Тексты (`--lyrics-format`)

| Значение | Поведение |
|---|---|
| `NONE` (по умолчанию) | не запрашивать |
| `TEXT` | текст **в теги** (`USLT` / `©lyr` / Vorbis `LYRICS`), файла рядом нет |
| `LRC` | рядом файл `<название>.lrc`; если синхронного текста нет — в теги резервом кладется обычный текст |

Отсутствие текстов — это пустой источник Яндекса, а не ошибка.

### Теги по форматам

* **MP3** — ID3v2.4, а с `--compatibility-level 1` — **ID3v2.3**: `TIT2 TALB TPE1 TPE2 TDRC TRCK TPOS TCON USLT APIC WOAF`. Перед записью старые `USLT`/`APIC` удаляются — дублей кадров не появляется.
* **M4A** — атомы: `©nam ©alb ©ART aART ©day trkn disk ©gen ©lyr covr ©cmt` (номера трека/диска — целые числа).
* **FLAC** — Vorbis: `TITLE ALBUM ARTIST ALBUMARTIST DATE TRACKNUMBER DISCNUMBER GENRE LYRICS` + `METADATA_BLOCK_PICTURE`; перед врезанием новой обложки старые картинки из файла снимаются, так что дублей изображений нет.
* Ссылка на трек: `WOAF = https://music.yandex.ru/track/<id>` / `©cmt` / `comment` — во всех трёх форматах.
* Год собирается по цепочке `album.year → album.release_date → track.pub_date`.
* Не удалось записать теги — файл остаётся скачанным, печатается `⚠️ Теги не записаны: …`.

## 10. Отбор треков

* `--stick-to-artist` — для источника «артист»: только релизы/треки, где артист основной.
* `--only-music` — для источника «артист»: пропускает немузыкальные релизы (`meta_type=podcast`, аудиокниги и т.п.). Если у артиста только аудиокниги, будет `Найдено треков: 0` и `rc=0` — это корректная работа фильтра, а не ошибка.
* Недоступные треки: `🚫 … (НЕДОСТУПЕН)`; список — `--save-unavailable`.

## 11. Режимы и отчёты

| Ключ | Результат |
|---|---|
| `--list-only` | ничего не качает; файл `tracks_list_<YYYYMMDD_HHMMSS>.txt` (строки `Артист - Название` без отступов в начале, недоступные `🚫 … (НЕДОСТУПЕН)`); в консоли `Найдено треков: N`, `Список сохранён: <путь>` |
| `--save-unavailable` | `unavailable_tracks_<timestamp>.txt`, создаётся только если были недоступные |
| `--recheck` | сканирует `--dir` и пишет `bitrate_report_<timestamp>.txt` с фактическими битрейтами. **Проверяет только `.mp3`** (см. раздел 18). Работает без источника, токена и сети |

```
✅ Скачано: 20
⏭️ Пропущено (уже есть): 0
🚫 Недоступно: 0
❌ Ошибки: 0
📝 Всего: 20
```

## 12. Сеть и надёжность

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `-t`, `--token` | — | OAuth-токен (см. раздел 3) |
| `--tries N` | `20` | число повторов неудачного запроса |
| `--retry-delay SEC` | `5` | пауза между повторами |
| `--delay SEC` | `0` | пауза между треками (рекомендуем `1` — заметно снижает риск `429`) |
| `--timeout SEC` | `20` | таймаут запроса/скачивания |
| `--proxy URL` | — | например `socks5://127.0.0.1:1080` (нужен `pysocks`) |
| `--no-check-certificate` | выкл | отключить проверку TLS (с предупреждением) |

* Сетевые сбои, таймауты и `429` повторяются автоматически (`--tries`, `--retry-delay`).
* **Ошибки «запрос заведомо неверный» не повторяются**: `404 Not Found`, `400 Bad Request`, `401/403 Unauthorized` (мёртвая ссылка, неверный ID, просроченный токен, приватный плейлист) завершают прогон сразу с понятным текстом — вместо бессмысленных 20 повторов. Остальное (`429`, `5xx`, обрывы связи, таймауты) библиотека отдаёт как `NetworkError`, и такие запросы повторяются по `--tries` и `--retry-delay`.
* Числовые параметры CLI принимают только допустимые значения: `--tries` и `--timeout` — целые **≥ 1**, `--retry-delay` — целое **≥ 0**, `--delay` — число **≥ 0**, `--cover-resolution` — `original` или число **≥ 100**. Например, `--timeout 0` или `--tries -1` — ошибка разбора аргументов с кодом `2` (`argument --timeout: '0' must be at least 1`).

## 13. Коды возврата

| Код | Когда |
|---|---|
| `0` | успех, в том числе «Не найдено треков» (например `--only-music` по артисту-аудиокниге) |
| `1` | ошибка (мёртвая ссылка, приватный плейлист, чужой `likes`, сбой авторизации, сетевой провал после повторов) |
| `2` | ошибка разбора аргументов (нет источника без `--recheck`, неверное значение ключа, `--force-mp3` не с `-q 0/1`) |
| `130` | Ctrl+C |

## 15. Примеры

Ниже — команды установленной программы (`pipx` или `pip`). Без установки заменяйте `ymd` на `python -m ymd`.

**Один трек в максимальном качестве**
```bash
ymd --url https://music.yandex.ru/album/34454581/track/134036245 -q 2
```
FLAC-поток пересобирается (ремукс) в `.flac` (Vorbis-теги + `METADATA_BLOCK_PICTURE`); если lossless нет — лучший lossy-поток источника **обязательно конвертируется в `.mp3`** с битрейтом источника (сырого `.m4a` не будет).

**Альбом AAC 192, «докачать» только новое**
```bash
ymd --url https://music.yandex.ru/album/36526 -q 1 --dir D:\Music --skip-existing
```
Уже лежащие файлы → `⏭️ Пропущено (уже есть)`.

**Артист: MP3 максимум, без аудиокниг и featuring**
```bash
ymd --url https://music.yandex.ru/artist/25114406 -q 320 --stick-to-artist --only-music
```
Запрошенный 320 берётся из FLAC, если lossless есть (CBR 320 через FFmpeg); для lossy-источника битрейт не превысит API-значение (например, даст 256).

**«Мне нравится» своего аккаунта и чужого**
```bash
ymd --playlist-id likes -q 1 --list-only
ymd --url https://music.yandex.ru/playlists/lk.<uuid> -q 1
ymd --url https://music.yandex.ru/users/<login>/playlists/3 -q 1
```
Списки последних двух команд идентичны, если `<login>` — владелец этого `lk.<uuid>` (это один и тот же плейлист, записанный по-старому и по-новому); чужой keyword `likes` даст понятную ошибку с подсказкой взять `lk.<uuid>` или старый адрес `…/playlists/3`.

**Сохранить AAC, но получить MP3**
```bash
ymd --album-id 36526 -q 1 --force-mp3
```
Без FFmpeg в `PATH` — предупреждение, файлы останутся `.m4a`, прогон не падает. С `-q 2/192/256/320` этот флаг запрещён (код `2`) — эти режимы и так всегда отдают `.mp3`/`.flac`.

**Только список и недоступные треки**
```bash
ymd --url https://music.yandex.ru/artist/16313518 --list-only --save-unavailable
```

**Многодисковый альбом: нумерация по томам + год в пути**
```bash
ymd --album-id 36526 -q 2 --path-pattern "{album_artist}/{year} - {album}/CD{disc_number}/{real_track_number_padded} - {title}"
```

**Обложка отдельным файлом, текст в теги**
```bash
ymd --album-id 30325160 --no-embed-cover --lyrics-format TEXT --cover-resolution original
```

**Максимальная совместимость тегов (старые плееры)**
```bash
ymd --album-id 36526 -q 2 --compatibility-level 1
```
FLAC не запрашивается ни при `-q 2`, ни при `-q 192/256/320`, MP3 получит теги ID3v2.3.

**Отчёт фактических битрейтов скачанного (без сети и токена)**
```bash
ymd --dir D:\Music --recheck
```

**Прокси, паузы, таймаут, токен из `.env`**
```bash
ymd --album-id 41097326 -q 2 --proxy socks5://127.0.0.1:1080 --delay 1 --tries 4 --retry-delay 3
```
Токен при этом можно не передавать: он возьмётся из `./.env` или `~/.ymd/.env`.

## 16. Что вошло в версию 0.0.2

**Логика качества (переписано ядро `core/quality.py`)**
* `-q 192/256/320` теперь **всегда проверяют FLAC**: запрос потока идёт с `quality=lossless` и кодеком `flac`. Есть FLAC → lossless-поток скачивается и перекодируется FFmpeg в **чистый MP3 запрошенного битрейта (CBR)**. Нет FLAC → прежнее правило `min(запрошенный, источник)`.
* `-q 2` без FLAC больше **не оставляет сырой `.m4a`**: lossy-поток обязательно конвертируется в `.mp3` с битрейтом источника (например `AAC 256 → MP3 256kbps`).
* `-q 0` и `-q 1` не изменились: родной `.m4a` (AAC 64 / 192), FLAC не опрашивается; `--force-mp3` по-прежнему гоняет их в MP3 CBR 64/192.
* Если источником уже является MP3/bitrate, равный запрошенному, FFmpeg не вызывается вовсе (файл сохраняется как есть).
* Выбор потока вынесен в `core/quality.py` (`select_download_info` → `(download_info, ConversionPlan)`); `ConversionPlan` описывает целевой кодек, битрейт, режим (транскодирование / ремукс / stream copy) и тексты для лога.
* FFmpeg при транскодировании логирует команду человека-читателю (`[FFmpeg] Транскодирование: FLAC -> MP3 320kbps CBR`) и переносит теги исходника (`-map_metadata 0`); итоговые теги всё равно пишет `metadata/tags.py`.
* `--compatibility-level 1` усилен: FLAC **не запрашивается ни в каком режиме** (ни `-q 2`, ни `-q 192/256/320`), плюс двойная защита — если API всё равно вернул lossless-поток, он игнорируется с предупреждением.
* Шапка запуска печатает **фактическое** качество: `Качество: -q 320 → MP3 320kbps CBR (FLAC проверяется; без FLAC — не выше источника)` — с учётом `--force-mp3` и `--compatibility-level`. Это страховка от тихой потери флага `-q` (реальный случай: ссылка с `&` без кавычек в cmd → запуск с `-q 0`, и вместо MP3 320 получился AAC 64 `.m4a`). Реализация: `core/quality.py:mode_description`; в `--recheck` без источника строки нет.

**Проверено живыми прогонами** (acceptance-наборы задачи):
* трек с FLAC `album/16554671/track/81924969`: `-q 320` → lossless скачан и перекодирован в MP3 **ровно 320000 бит/с** (mutagen); `-q 2` → `.flac` (ремукс);
* трек без FLAC `album/36526/track/361165` (AAC 192): `-q 320` → MP3 **192000 бит/с** (апскейла нет); `-q 2` → обязательный `.mp3` 192000 бит/с с полными тегами;
* `--compatibility-level 1`: при `-q 320` и при `-q 2` FLAC проигнорирован, на диске MP3 256000 бит/с с тегами **ID3v2.3**.

**Контекстные шаблоны сохранения (`--path-pattern`)**
* Если `--path-pattern` **не передан**, шаблон выбирается автоматически по типу распознанного источника — таблица в разделе 7. Реализация: `filesystem/paths.py` (`SourceType`, `DEFAULT_PATTERNS`, `select_default_pattern`) + `cli/main.py`; прежний единый шаблон-константа из `config.py` убран.
* Тип источника определяет `api/resolver.py` (`LinkResolver.resolve_source` → `ResolvedSource(source, source_type, playlist_title)`): трек, альбом, дискография артиста, треки артиста, подкасты артиста, плейлист.
* Добавлены маршруты `…/artist/<id>/tracks` (пагинация `GET /artists/<id>/tracks`) и `…/artist/<id>/podcasts` (у API отдельного маршрута подкастов нет — берутся релизы артиста с `meta_type == 'podcast'`); автоплейлист `ar.<uuid>` относится к «трекам артиста».
* Новый плейсхолдер **`{playlist}`** — оригинальное название плейлиста из Яндекс Музыки (`playlist.title`, при пустом — `Плейлист`). Вне плейлистов он пустой, пустые сегменты пути схлопываются, поэтому пустой папки не появляется.
* В консоли всегда печатается, какой шаблон действует: `Шаблон пути выбран по типу источника (альбом): …` или `Шаблон пути (указан пользователем): …`.
* Проверено живыми прогонами: одиночный трек без шаблона лёг **прямо в `--dir`** без промежуточных папок; плейлист — в папку `Детский треш` (оригинальное имя из API); `…/artist/23098383/podcasts` и `…/artist/47/tracks` распознаны как «подкасты артиста»/«треки артиста» с шаблоном `{artists}/{artists} - {title}` (112 и 80 треков).

**Установка и документация**
* В README добавлен раздел **2.6 «Установка из GitHub»**: `pip`/`pipx` + `git+https://github.com/ytd-dev/ytd.git`, варианты с тегом (`@v0.0.2`), веткой (`@main`) и коммитом, extra `proxy`, обновление и проверка версии после установки. Репозиторий лежит в той же раскладке (`pyproject.toml` + пакет `ymd/` в корне), поэтому `#subdirectory=` не нужен.
* Быстрый старт (раздел 1) теперь начинается с установки из GitHub, в требованиях (раздел 2.1) отдельной строкой указан `git` для этого способа.
* Раздел 5 дополнен предупреждением про кавычки: в cmd/bash `&` в ссылке делит командную строку пополам, и запуск уходит вообще без `-q` (в PowerShell неэкранированный `&` делает строку неразбираемой). Раздел 6 показывает, где видеть фактическое качество (`Качество: …` в шапке).

## 17. Что вошло в версию 0.0.1

**CLI и вывод**
* Ключи `-v` / `--version`: печать `ymd 0.0.1` и выход с кодом `0`; версия также видна в описании `--help` (`YMD (v0.0.1) — …`) и в шапке консоли при каждом запуске — `Загрузчик треков Yandex Music (ymd v0.0.1)`.
* В отчёте `--list-only` строки треков пишутся без ведущих отступов: `Артист - Название`, недоступные — `🚫 … (НЕДОСТУПЕН)`.
* В подсказке device flow теперь показаны оба адреса подтверждения: рабочий `verification_url` (обычно `https://ya.ru/device`) и прямой `https://oauth.yandex.ru/device`.

**Безопасность файловой системы**
* `--overwrite` и защита от случайной перезаписи: FFmpeg вызывается с `-y` только при явном `--overwrite`, иначе с `-n`; при конфликте имён создаётся `файл (1).mp3`.
* Успех конвертации засчитывается только если целевой файл реально создан/перезаписан в этом запуске (FFmpeg 9.x возвращает код 0, ничего не записав, — это больше не считается успехом). Исходный файл при неудаче сохраняется.
* Скачивание идёт во временный `.part` с последующим переименованием: оборванная загрузка не оставляет файл «готовым» и не мешает докачке; `.part` удаляются при ошибке.
* `--skip-existing` проверяет именно целевой каталог трека (по расширениям `.mp3/.m4a/.flac/.mp4`), а не всё дерево загрузки.

**Сеть**
* `404 / 400 / 401·403` больше не ретраятся по 20 раз — прогон сразу завершается внятной ошибкой; сетевые сбои, таймауты и `429` по-прежнему повторяются.
* Валидация числовых параметров CLI (`--timeout` и др.): `0` и отрицательные значения отвергаются с кодом `2`.

**Теги и обложки**
* `--compatibility-level 1` теперь влияет и на контейнер (без FLAC), и на теги MP3 (**ID3v2.3** вместо v2.4).
* Нет дублей метаданных: перед записью в MP3 снимаются старые `USLT`/`APIC`, в FLAC — старые вложенные изображения.
* MIME-тип обложки определяется по содержимому байтов, корректно в том числе при загрузке из кэша `~/.ymd/covers`.
* Ссылка на трек в тегах (`WOAF` / `©cmt` / `comment`) работает во всех форматах; год ищется по цепочке `album.year → release_date → track.pub_date` (подкасты больше не остаются без года там, где он есть в API); номера трека/диска в MP4 пишутся целыми числами.

**Токен и конфигурация**
* Поиск токена: `--token` → `YANDEX_MUSIC_TOKEN` → `.env` (`./.env`, затем `~/.ymd/.env`) → device flow.
* Device flow **автосохраняет** токен в `~/.ymd/.env` (с правами `0600` на POSIX), повторный вход не нужен; `.env` добавлен в `.gitignore`.
* Парсинг `.env` — только стандартная библиотека, новых зависимостей у проекта нет. Файл, сохранённый в UTF-8 с BOM (Блокнот, PowerShell 5.1), читается корректно: BOM снимается при чтении, строка `YANDEX_MUSIC_TOKEN=` распознаётся, дубликаты при автосохранении не появляются.

**Источники**
* Корректное разрешение ссылок `lk.<uuid>`, `ar.<uuid>`, UUID, старого формата `users/<login>/playlists/<kind>` и keyword `likes`; чужой `likes` — явная ошибка вместо подмены своими лайками.

## 18. Известные ограничения

Критических (неработоспособность, порча или некорректное скачивание файлов) **нет**. Открытые:

| Ограничение | Влияние | Статус / что делать |
|---|---|---|
| `--recheck` проверяет битрейты только `.mp3` | `.m4a` и `.flac` не попадают в `bitrate_report` | в плане расширения на все контейнеры |
| Без FFmpeg режимы, где план требует конвертацию (`-q 2` без FLAC, `-q 192/256/320` не из нативного MP3 своего битрейта), оставляют файл в нативном формате (например `.m4a`) | в этих режимах без FFmpeg «гарантия MP3» не выполняется | поведение намеренное (прогон не прерывается); установите FFmpeg |
| Метаданные подкаст-аудиокниг, найденных через артиста, бывают неполными (пустые `DATE`, `GENRE`) | файлы играются нормально, но тегов меньше | объект из листинга артиста не обогащается запросом к API; в плане — дозапрос `client.tracks`/`client.albums` при пустом годе |
| Обложка может быть меньше запрошенного размера (родной размер CDN, апскейла нет) | выглядит как «потеря качества», но это максимум источника | планируется предупреждение вида `у источника максимум NxN` |
| Чужой keyword `likes` (`users/<login>/playlists/likes`) не пробует старый адрес `…/playlists/3`, который работает | нужно вручную взять `lk.<uuid>` | в плане — fallback на старый маршрут и подсказка в тексте ошибки |
| Свои лайки по разным маршрутам (`…/playlists/3` и `likes`) могут немного различаться по составу | две корректные ссылки дают слегка разный результат | особенность API; зафиксировано в документации (раздел 5) |
| `--force-mp3` без FFmpeg — только предупреждение | файл остаётся `.m4a` | поведение намеренное (прогон не прерывается) |
| MP3 по умолчанию пишется с ID3v2.4 | очень старые плееры и авто могут не увидеть часть тегов | использовать `--compatibility-level 1` |

Не является недостатками: `.mp3` у подкастов без AAC-потока; «уменьшенная» обложка при родном размере меньше запрошенного; фактический VBR-битрейт ниже заявленного для AAC; пустые тексты там, где их нет в API; укороченный путь при пустых `{year}`/`{disc_number}`; код возврата `1` на мёртвых ссылках.
